ROUND 3：Production QAを実行してください。
Figma_Vanilla_ClaudeCode_3Pass_Implementation_Kit.mdとCLAUDE.md、
docs配下の案件情報・監査・判断ログ・ROUND 1/2のQA結果を読み、
ROUND 2の見た目を維持したまま実装品質を仕上げてください。
問題の列挙だけで終了せず、変更範囲内の修正と検証まで行ってください。

1. 配信・基本品質
- 実際に納品する静的ファイル構成をHTTPサーバで確認する。
- CSS/JS/画像/フォントの参照、404、コンソールエラー、ID重複、
  不正なHTML、相対パス、サブディレクトリ配信を確認する。
- CSS結合等をするなら順序・layer・URLを保ち、生成物を再検証する。
- READMEにセットアップ、起動、必要ならビルド、検証方法を書く。

2. レスポンシブ・操作
- 参照幅、対応範囲の検証幅、BP前後1pxを確認し、実施幅を記録する。
- 横はみ出し、意図しない重なり、長い文言、文字拡大、リフローを確認する。
- 存在するメニュー、開閉UI、アンカー、フォーム等をマウスとキーボードで操作する。
- 固定要素がある場合、見出しやフォーカス先を隠さないことを確認する。
- JS無効・読込失敗時、画像やフォント失敗時の状態を確認する。

3. a11y
- lang、title、ランドマーク、見出し階層、読み上げ順、リンク名、
  ボタン名、alt、フォームのlabelとエラー通知を確認する。
- Tab/Shift+Tab、Enter/Space、必要なEscape、フォーカス復帰を実操作する。
- モーダルと通常メニューを区別し、適切なフォーカス管理を行う。
- コントラスト、操作対象のサイズ/間隔、拡大・リフロー、
  reduced-motionと必要なメディア代替を検証する。
- 自動チェックに加えて手動確認を行い、ツール名・範囲・未確認を記録する。
- 色・タイポ・サイズ等の変更が必要な問題は無断変更せず、
  影響と修正案をNEEDS_APPROVALとして残す。未解決を合格扱いにしない。

4. 表示性能
- 実測したLCP候補、画像容量と解像度、読み込み優先度、
  フォント、レイアウトシフト、JS処理を確認する。
- 画像・フォント等を最適化する場合、品質・文字欠け・cropを再確認する。
- LCP 2.5秒以下 / CLS 0.1以下 / INP 200ms以下を品質目標とする。
- ツール、端末相当条件、ネットワーク、キャッシュ、URL、試行数を記録する。
- ローカルのラボ計測と実ユーザーデータを区別する。
  実ユーザーデータ未取得なら本番Core Web Vitals達成と断定しない。
  INPを測れない場合は未計測とし、TBT等で代替合格にしない。

5. リンク・コンテンツ・メタ情報
- 案件情報のリンク表と実装を照合する。内部アンカーは存在まで確認する。
- 外部リンクの設定と到達性、ファイル取得、mailto/telの値を確認する。
  取得制限等で確認できない場合は無効と断定せず、未確認と記録する。
- フォーム等は許可されたテスト環境で検証し、本番の実送信を勝手に行わない。
- title、description、OGP、favicon、canonicalは確定した情報のみ設定する。
- 構造化データは内容・用途・根拠が適合する場合だけ追加する。
  FAQ等の存在だけを理由に一律で追加しない。
- UNKNOWN、仮素材、仮リンク、未接続を列挙し、公開可能な状態かを判定する。

6. 見た目の回帰確認
- 修正後にROUND 2と同じ条件で主要幅を再撮影する。
- ROUND 2の画像と比較し、Figma参照も確認する。
- 性能・a11y修正による文字、色、画像、寸法、余白、操作状態の変化を確認する。
- 許可されていない見た目の変更は差し戻す。
- docs/spacing-audit.md、assets.md、implementation-decisions.mdを更新する。

7. 納品判定
- docs/qa-round3.mdにPASS / FAIL / BLOCKED / NOT_TESTED / N/Aで結果を記録する。
  N/Aは対象が存在しない等の理由を添える。
- 実装完了、検証完了、公開可能を分けて判定する。
- 必須素材・フォント・リンク・仕様・品質要件が未解決なら公開可能としない。
- 公開そのものは、このプロンプトでは実行しない。

最後に、納品ファイルと確認方法、実施テスト、測定結果と限界、
最終比較画像、残るBLOCKER/承認事項、公開可否を簡潔に報告してください。
