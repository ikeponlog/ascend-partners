Phase 1：実測トークンとspacing監査
1. 色・タイポ・角丸・影・寸法は実測どおりにtokens.cssへ定義する。
   書体はFONT SPECを確認し、役割変数で参照する。
2. 余白を役割・文脈・viewportで分類し、docs/spacing.mdに従い
   維持 / スナップ / 統一 / 承認済み例外 / 保留を判定する。
3. docs/spacing-audit.mdに元値・採用値・差・根拠・副作用を記録する。
   4pxスケールや共通paddingを強制せず、根拠が弱い箇所は元値を維持する。
4. docs/implementation-decisions.mdに判断と再確認事項を残す。
   このPhaseの承認待ちで全体を停止しない。

Phase 2：素材
1. 正式素材を取得し、site/assets/へ保存する。使用するカテゴリだけ作成する。
2. 元素材・ノード・表示寸法・crop・alt・読込方針・権利確認・取得状態を
   docs/assets.mdへ記録する。

4. 取得失敗・手動書き出しが必要な素材を区別し、依存しない箇所を進める。
   このPhaseも承認待ちで全体を停止しない。

2. コンテナ幅、ボタン、見出し、ヘッダー、フッター等はFigmaの

4. 必要な検証ツールはこの案件で作成・設定し、READMEに起動方法を記載する。
   他案件のcompare.mjs等がある前提で進めない。
