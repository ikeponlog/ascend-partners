# スクリーンショット比較とレスポンシブ

### 6-1. 比較条件

1. 同じ参照フレーム幅、同じDPR・書き出し倍率、同じ操作状態で撮る。Figmaの2x PNGならブラウザも同条件に揃えるか、共通倍率へ正規化した手順を記録する。
2. 使用ブラウザ・バージョン、viewport幅と高さ、DPR、ズーム、撮影日時、コードの状態を保存する。
3. フォント読込と画像decode完了を待つ。lazy画像は必要範囲をスクロールして読み込み、撮影位置に戻す。動画・時刻等の変動要素は条件を固定し、マスクが必要なら範囲と理由を残す。
4. 静止画QAでは、指定アニメーションを決定的な終了状態にする。動作QAは通常動作とreduced-motionを別途確認する。リビール待ちで本文が消えた状態を比較しない。
5. 全ページ、セクション単位、主要なUI状態の画像を保存する。横並び、半透明overlay、diffを用意する。
6. セクション比較で合わせてよいのは参照対象の原点と等倍条件まで。要素ごとの自動位置補正・拡大縮小・画像変形でずれを隠さない。
7. セクション高が違う場合、切り捨てて同じ高さにしない。共通キャンバスへの余白追加等で差を可視化し、全ページ比較で累積ずれも確認する。

比較スクリプトを作成する場合は、入力画像・ノード・幅・倍率・出力先を指定できる構成にする。サイズ不一致を検出し、正規化の内容を記録する。差分率だけで自動合格にしない。

### 6-2. 差分の分類と合否

| 分類 | 例 | 対応 |
|---|---|---|
| A：監査済み余白 | 採用したgap変更 | 記録と一致し、印象も維持できている場合のみ許容 |
| B：微細な描画差 | 同じ書体・行数・字幅でのアンチエイリアス差 | 環境差の根拠を残す。数値をゼロまで追わない |
| C：実装ミス | コピー欠落、別フォント、色違い、crop違い、整列・改行・寸法のずれ | 原因を修正し、該当範囲と全体へ回帰確認 |
| D：未解決・比較不能 | 参照未取得、素材不足、未承認の代替 | BLOCKERとして残す。合格にしない |

字幅・行数・改行・要素高さが変わる差は、安易にBに分類しない。差分率が小さくてもCTAやコピーの欠落があれば不合格。高さ差±5%は調査目安であり、許容される再設計幅ではない。

印象チェック：密度感、情報の強弱、視線の流れ、整列軸、色の面積比、余白のリズム、写真と装飾の重なり、CTAの目立ち方を確認する。「以前より強調できた」を合格条件にしない。

### 6-3. レスポンシブ方針

- PC/SPの参照があれば、それぞれの幅で忠実に合わせる。モバイルファーストのCSSでも、参照の情報構造を変えない。
- ブレークポイントは内容が破綻する幅と承認フレームから決める。PC/SPのフレーム幅そのものを無条件にブレークポイントにしない。
- 中間幅では自然な折返し・Grid/Flex・最大幅を使う。`clamp()`は端点と変化が妥当な値に限り、文字サイズや行間を勝手に流動化しない。
- SP参照がない場合、情報順序・色・書体・画像・CTAの強弱を保つ最小限の組み替えを記録する。PC全体の一括縮小や根拠のない並べ替えはしない。
- SP案は「実装上の仮定」とし、承認済みSPの再現とは報告しない。複雑な図のリスト化など表現変更が必要な箇所は承認対象にする。
- 参照フレーム幅に加え、320 / 375 / 393 / 768 / 1024 / 1280 / 1440 / 1920pxと、採用BPの前後1pxを検証候補にする。案件の対応範囲に応じた実施幅を記録する。
- 200%拡大、320 CSS px相当のリフロー、長い文言・入力値による破綻も確認する。正当な例外を除き横スクロール、重なり、欠落を防ぐ。
- `overflow-x: hidden`をページ全体に付けて原因不明のはみ出しを隠さない。装飾の意図的な裁ち落としだけ局所的に扱う。
