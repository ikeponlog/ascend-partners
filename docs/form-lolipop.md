## 迷惑メール・悪用への対策

- 利用者宛てのメール（#1・#4）には、入力された自由な文を一切載せない（結果は設問IDを `result-copy.json` で文言に置き換えるだけ）。他人のアドレスを入れられても、踏み台として任意の文を送れない。
- 同じサイトのページからの送信だけ受け付ける（Origin / Referer のホスト確認）。POST・JSON・16KBまで。
- 人には見えない入力欄（`website`）に値があれば、送ったふりをして何もしない。
- 同じ接続元から10分に5回まで（`config.php` の `rate_limit`）。記録は `api/data/rate/`（IPはハッシュ化）。
- メールアドレスの形式・長さの確認、改行の除去（ヘッダーの書き換えを防ぐ）。
- `api/` の中は `send.php` 以外をブラウザから開けない（`.htaccess`）。PHPの警告は応答に出さない。

## ロリポップへの設置手順（アドレスと文面が決まってから）

1. **プラン**：PHPが使えるプラン（ライト以上）。ロリポップ!管理画面の「PHP設定」で、サイトのディレクトリを **PHP 8.1 以上**（推奨 8.3）にする。
2. **送信元アドレス**：独自ドメインを設定し、「メール」でこのドメインのアドレスを作る（例：`no-reply@<ドメイン>`。受信できるアドレスにしておくと、宛先不明の戻りメールを確認できる）。
3. **送信ドメイン認証**：迷惑メール判定を避けるため、ドメインの DNS に SPF を設定（ロリポップの案内値）。DKIM・DMARC も設定できれば設定する。
4. **アップロード**：`npm run build` 後の `dist/` の中身を公開ディレクトリへ（FTP / ロリポップ!FTP）。`api/.htaccess` も含める（ドットで始まるファイルが隠れて転送漏れしやすい）。
5. **設定**：サーバー上の `api/config.php` を編集する。
   - `mail_from`：手順2のアドレス
   - `notify_to`：事務所の受信アドレス
   - `allowed_hosts`：公開するホスト名（例：`['example.jp', 'www.example.jp']`）。メール内のURLも先頭のホストで作る
   - `consult_url`：メール内の30分相談のURL（空ならサイトの `diagnosis/#consult`）
   - 初回は `dry_run => true` にして、フォームから送信 → `api/data/outbox/` に内容が保存されることを確認（ブラウザからは見えない。FTPで確認）
6. **実送信の確認**：`dry_run => false` に戻し、自分のアドレスで両方のフォームを送信。受信・迷惑メールフォルダ・文字化け・返信先を確認する。
7. **確認後**：`api/data/outbox/` を削除。
8. **WAF**：ロリポップのWAFが送信を誤って止める場合がある（画面は「送信できませんでした」になる）。管理画面の「WAF設定」のログで確認し、必要なら一時的に無効化して原因を特定する。

### ファイルの書き込み

`api/data/`（連続送信の記録・確認用の保存）は `send.php` が自動で作る。作れない場合は「500 storage」になるので、FTPで `api/data` を作り、パーミッションを 700（または 705）にする。

## ローカルでの確認

PHPのインストールは不要（Node 上の PHP 8.3、`@php-wasm/node`）。

```bash
npm run build
```

`dist/api/config.php` だけを確認用に書き換える（`mail_from: no-reply@example.com`、`notify_to: office@example.com`、`dry_run: true`。`site/` 側は空欄のまま）。

```bash
npm run serve:php
```

```bash
npm run check:api
```

- `http://localhost:3200/diagnosis/?demo=email` などで画面から送信でき、内容は `dist/api/data/outbox/` に保存される。
- 終わったら `npm run build` で `dist/` を作り直す（config.php が空欄に戻る）。
- PHPを実行しない `npm run serve:dist`（3100）では、送信すると「送信できませんでした」画面になる（正常）。
