# 余白の統一ルール

## 目的
同じ役割・同じ文脈の余白を揃え、承認済みの密度感と視線の流れを保つ。
すべてのセクションを同じpaddingにすることは目的ではない。

## 対象と対象外
対象はmargin / padding / gapによる要素間隔・内側余白。
行間・字間・文字サイズ・幅・高さ・画像比率・装飾座標・重なりは対象外。
padding変更で要素寸法や改行が変わる場合も副作用として検証する。
高さを固定して内容を切る、負のmarginで無理に打ち消す等の補正をしない。

## スケールの決め方
1. Figmaの変数・既存スケールがあれば最優先で採用する。
2. なければPC/SPごとに実測値を集め、役割と文脈で分類する。
3. 頻出値・中央値・強弱の意図を確認し、最小限の共通スケールを作る。
4. 4pxベースは候補にすぎない。合わないデザインへ強制しない。

参考候補（そのまま採用する既定値ではない）：
0, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80, 96, 120px

役割トークンの例（必要なものだけ採用）：
--section-space-default / --section-space-compact / --section-space-emphasis
--heading-label-gap / --heading-lead-gap / --heading-content-gap
--card-padding / --card-gap / --stack-gap / --action-gap / --page-gutter

PC/SPの値は別々に実測し、同じトークンのviewport別定義として管理する。
例外はセクション専用トークンとし、理由を監査表に記録する。

## 判断手順
1. 実測値が既存スケールに沿う、または意図された構図なら「維持」。
2. 同じ役割・文脈のばらつきだけを「統一」候補とする。
3. スケール外の小差は「スナップ」候補とする。
4. 自動適用候補の上限は、元の値との差が4px以下かつ20%以下。
   元が0なら維持。これは保守的な運用目安であり、変更の義務ではない。
5. 上限内でも改行・寸法・整列・グループ関係・密度感を損なうなら維持する。
6. 上限を超える候補、役割が曖昧なもの、意図された例外は「維持」または
   「保留」とし、候補・根拠を残す。ログだけで変更を正当化しない。
7. 変更前後の比較で問題が出たら元に戻し、例外として記録する。

## 監視する指標
- セクション高さ差(%) = (実装高 - Figma高) / Figma高 × 100。
- 絶対値5%超を再調査の目安とする。5%以内でも印象が違えば不合格。
- 全ページの高さ、主要見出し・画像・CTAのy位置も確認する。
- 参照のない画面幅にはFigma比を作らず、「参照なし」と記録する。
- 原因が余白か、フォント・幅・画像寸法・折返し等かを分離する。

## UI/UXとa11yの扱い
- グループ内とグループ間の大小関係を保つ。固定の比率を押しつけない。
- すべてのカードを16px以上、本文行間を1.8、行長を40文字にする等の
  一律変更は行わない。既存タイポと構図を維持する。
- タップ領域は案件のa11y目標に照らして確認する。
  必要なら見た目を変えずにヒット領域を広げ、隣接要素との干渉を防ぐ。
- ボタンの見た目を一律の高さに変えない。視覚的な変更が必要なら
  影響と案を記録し、変更承認を待つ間も他の作業を続ける。
