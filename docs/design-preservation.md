# 優先順位と変更の境界

### 優先順位

1. **承認済みデザインの維持**：コピー、情報階層、色、書体、構図、レイアウト、画像、装飾、CTAの強弱を維持する。
2. **余白の統一**：同じ役割・同じ文脈の余白だけを、監査済みのルールに揃える。
3. **実装品質**：正しい構造、操作性、レスポンシブ、アクセシビリティ、表示性能、リンクの正確性を確保する。

下位の目的を理由に上位を変更しない。「CVを上げる」「読みやすくする」「今風にする」を理由に、文言・サイズ・色・構成を再設計しない。

ただし、承認済みデザインとa11y要件などが両立しない場合は、問題を隠して合格にしない。見た目を維持したまま解決できる実装を先に行い、視覚的変更が必要なら変更案と影響を記録する。その箇所の変更は明示的な承認を得てから行い、それ以外を進める。

### 変更の境界

| 項目 | 扱い |
|---|---|
| `margin`、`padding`、`gap`による余白 | 監査・記録・比較を満たす範囲で統一可能 |
| 意図された大きな空白、非対称、重なり、裁ち落とし | 構図として維持。通常の余白と同一視しない |
| 色、グラデーション、透明度、フォント、サイズ、ウェイト、行間、字間 | Figmaを維持。余白調整に含めない |
| コピー、句読点、数値、ラベル、強調箇所、情報順序 | 完全維持。誤字に見えても無断修正しない |
| 要素幅・高さ、画像比率、トリミング、角丸、影、装飾位置 | Figmaを維持。余白統一の副作用による変化も検出する |
| 意図的な見出し改行 | 参照フレーム幅で維持。中間幅では欠落や横はみ出しを防ぐ |
| HTMLの意味構造、名前・状態の付与、キーボード対応 | 見た目を維持して改善可能 |
| 未指定の演出、追従ヘッダー、カルーセル、フォーム、FAQ | 新規に追加しない |
